# Selected context (#8)

Use **Add to chat** for the owning conversation, or **Send to agent…** to choose a task for selected context. The destination picker is task-only: an existing task or **New task** — work is meant to happen in scope of a task, which resolves the right conversation and checkout itself. Adding context opens the task's conversation immediately and never submits a prompt. The existing composer owns send, queue and provider capabilities. Same-session response quotes retain their session/message/provider/worktree origin. Selected-text actions reuse the existing compact menu; conversation issue sections use the standard chevron, and enabled actions use pointer cursors.

Task destinations resolve their conversation inside the task model: a linked or live task conversation wins, an unstarted task launches its children first, and **New task** opens the create sheet with the work items pre-linked and the changed working copy pre-selected — the send then continues on the new task's conversation. Choosing a task links each work item onto it (its Issues row and future sessions see the same ticket) and stages the snapshot on the resolved conversation. When the changed working copy belongs to the task project's repository family but is not a child yet, it is recorded on the task as an existing-copy child.

Inbox ticket handoff loads each selected ticket's title, URL, status and description through its provider adapter, saves its link and stages the snapshot in the existing issue-context card. Your next Send includes every selected snapshot; nothing is submitted automatically. The unified picker re-reads provider context at confirmation, so selections made against a stale ticket snapshot are refreshed. A single ticket offers detailed selection — description, discussion/comments counts, and files — shared with the Ask agent picker. Multiple tickets share one coarse selection (description on/off, a common recent-comment count, files on/off) applied to every selected item. Description-loading failure keeps the picker open with an error. Comments and files are not fetched by default. The ticket list stays beside the conversation. Clicking a row previews the ticket; **Back to conversation** restores the same composer and draft. The compact Issues row at the top of every conversation keeps all saved links and captured descriptions accessible after sending and reopening. Add issues opens Inbox selection beside that same conversation. Every linked ticket appears there once, including links added to existing conversations; the composer does not repeat those cards. Hide issues / Show issues collapses the Inbox list without remounting the conversation. Clicking a conversation issue card navigates to Inbox. Links reuse the existing persisted `linkedWorkItem` record, including before the first message.

PR and CI repair actions route through the same destination model. The picker preselects the task claiming the evidence checkout — or the task owning the source conversation when the sender knows it — and confirmation resolves the task child whose working copy exactly matches the evidence checkout, adding an existing-copy child when the task's repository family covers that path. Repairs never land on an unrelated session.

**Select tickets** replaces the filter toolbar with the selection count, **Open conversation** and **Done**. Once a conversation is open, selection edits its links directly and the redundant Open conversation button is hidden. Checkboxes edit persistent links while a conversation is open. **Done** exits selection without closing the conversation or changing its saved links. Selecting tickets again while that conversation is open edits its existing links. Leaving Inbox resets selection and its embedded conversation view; a new selection then starts empty. Project and provider dropdowns render above the destination dialog; Escape dismisses an open dropdown first. Context cards retain the existing InboxMiniCard appearance and preview; their remove buttons remove individual snapshots from the next message. The card list scrolls within 35% of the viewport (maximum 240 px), and Markdown is rendered only when a preview opens. Checkbox state updates immediately while the selected description loads; repeat selection reuses provider detail caches.

Text snapshots share a 32,000-character limit, divided fairly between entries with visible truncation so a long first issue does not erase later descriptions. Persisted ticket descriptions also share this budget across incremental additions; large descriptions receive an equal per-ticket share with a truncation notice. At most four selected-description requests run at once, and cancellation stops queued requests (already-started native requests may finish). Bundles allow at most 20 entries and existing attachment limits (20 files / 20 MiB). File content is captured through native IO. Changed-file context contains a highlighted patch built with the existing diff helper; provenance identifies staged/unstaged state and capture time, not an atomic commit snapshot. Selected source code keeps its file language in previews and sent messages. Right-click a diff line, or focus its comment control and press Shift+F10, to add/send only that displayed hunk with line locations. File and change capture bind the initiating session before asynchronous IO. Cancelling the recipient picker retains selected Changes files; selection clears only after successful preparation. Diff comments use a compact composer, and file selection uses the same checkboxes as Inbox. Binary/oversized diffs fail visibly. Unsupported attachment recipients are disabled. Unsent non-ticket context remains in memory like existing composer cards, including when its pane is detached; it is not restored after an app restart. Captured ticket text is retained in the existing linked-work-item JSON so it stays available after sending and reopening; legacy links without a saved snapshot still appear.

## Performance and remaining acceptance

On an Apple M5 Pro / 24 GiB Mac, minified production JS with 100 warmups and the median of 21 × 1,000 preparations of 20 ticket summaries measured 0.00685 ms for existing card preparation and 0.01091 ms for selected bundles. This excludes provider/network IO, WebView rendering, native app cost and agent/build processes. It is not an overall application benchmark. Hidden Inbox stops its foreground reads while retaining the mounted view; selected snapshots and lists are bounded. Incremental issue edits use existing debounced persistence rather than serializing the transcript for every checkbox; clearing a final blank-session link explicitly cancels its pending save and clears storage. Unchanged Inbox cards are memoized. A minified-JavaScript lookup benchmark with 500 visible tickets and 500 sessions of 20 links, 10 warmups and 21 samples, measured 29.09 ms median for repeated scans and 1.52 ms for indexed counts, with identical results. This measures only the lookup, excluding rendering, IPC and provider latency.

Still unverified: real multi-provider/streaming agent interaction, live Jira/Linear/GitLab/Azure account switching, full native changed-file/hunk interaction (browser hunk mouse/keyboard paths checked), Windows and Windows-to-WSL transfers. Screenshots below are browser component fixtures, not proof of full native rendering. Branch refresh now revalidates recent subfolders before publishing repository groups, preventing the temporary split and regroup that caused sidebar flicker; a regression test covers the slow subfolder probe. Keep the PR draft until the required live acceptance is reviewed.
